# ConsentPath · 隐私同意迁移演练台

全部在浏览器本地运行的隐私同意迁移演练工具。场景：产品把「体验优化」拆分为「分析」与「个性化」两个用途，不同地区沿用各自的同意规则；团队需要判断旧版同意迁到新版后哪些用途仍有效、哪些必须重新确认。

## 运行

```bash
npm install
npm run dev      # 开发服务器
npm test         # 运行测试（vitest）
npm run build    # 类型检查 + 生产构建
```

## 功能

- **版本与用途**：编辑说明版本与用途层级；草稿可编辑，发布后不可变；用途通过「迁移来源」（derivedFrom）声明与旧版本的关系，自动推导为 继承 / 更名 / 拆分 / 合并 / 新增。
- **地区规则**：每个地区独立的同意模式（opt-in/opt-out）、新用途显式同意、拆分重确认、合并策略、撤回级联开关。
- **用户与同意**：示例用户的同意矩阵；「未确认」= 无记录，按地区规则显示默认状态。
- **迁移演练**：实时预览旧同意如何映射到新版本（继承 / 按默认 / 待重新确认 / 失效 / 跳过 / 受阻），每条判定附来源与原因；支持单人/全量应用（幂等）、撤回（预览下游级联影响）、重新确认，操作日志逐条说明。
- **冲突检测**：版本分叉、用途合并分歧、循环引用、地区不匹配，均可一键定位到相关版本/用户并高亮用途。
- **工作台能力**：草稿/不可变发布版本、撤销重做、localStorage 刷新恢复、情景快照（保存/恢复/删除，且可撤销）。

## 结构

```
src/
  types.ts            领域模型
  domain/             纯函数领域逻辑（全部可单测）
    purposes.ts       用途树、映射推导、循环检测
    migration.ts      迁移引擎：判定 + 应用
    consent.ts        有效状态、撤回级联
    conflicts.ts      四类冲突检测（可定位）
    rules.ts          地区规则查找与回退
  state/
    store.ts          reducer + 撤销重做 + 持久化 + 快照
    seed.ts           示例数据（v1→v2 拆分、CN/US/EU 规则、5 位用户）
  components/         五个面板
tests/                版本迁移 / 部分撤回 / 重复操作 / 边界规则 / store / 冒烟
```

## 内置示例

- v1.0（已发布）：必要服务、体验优化
- v2.0（草稿）：体验优化 → 拆分为 分析（含 崩溃报告/使用统计 子用途）与 个性化；使用统计为新增用途
- 规则：CN（opt-in，拆分可继承）、US（opt-out，合并任一同意即可）、EU（opt-in，拆分需重确认）
- 用户：张伟(CN)、Alice(US)、Bob/Carol(EU，Carol 曾拒绝)、Dora(ATLANTIS，无规则 → 地区不匹配冲突)
